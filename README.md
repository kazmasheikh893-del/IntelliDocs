# IntelliDocs — AI-Powered Document Intelligence Assistant (RAG + Gemini)

Upload PDF/TXT documents, then ask questions in natural language. Answers are generated by the
official Google Gemini API **only from passages retrieved from your documents**, with citations
(document + page). If the documents do not contain the answer, the app replies exactly:

> The answer was not found in the provided documents.

## How RAG works here

1. **Upload & validate** – extension, size (default 10 MB), file signature (`%PDF-`), empty/binary checks, duplicate detection (SHA-256).
2. **Extract** – `pypdf` reads PDFs page by page (1-based page numbers kept); TXT is decoded (UTF-8/BOM, Latin-1/cp1252 fallback).
3. **Chunk** – overlapping chunks (default 800 chars / 100 overlap) that never cross a page boundary, each tagged with document + page.
4. **Embed** – `gemini-embedding-001` (768 dims, L2-normalised). Each chunk stores the model name and dimension.
5. **Store** – Django ORM (SQLite) + NumPy. Chunks and the "ready" status are written in one transaction; failures leave no partial data.
6. **Ask** – question embedded → cosine similarity over chunks of *ready* documents (optionally one document) → top-k above a threshold.
7. **Generate** – Gemini gets only those passages, fenced as untrusted data, and returns structured JSON (`answerable`, `answer`, snippet numbers).
8. **Cite** – the app validates snippet numbers against what was actually retrieved and builds filename/page citations itself. Invented references are discarded; an answer with no valid citation becomes the fallback.

A similarity threshold alone is not treated as proof of an answer: the model must also state the evidence supports it.

## Requirements

- Windows PowerShell (commands below), Python 3.11–3.13 (developed on 3.13), no native build tools needed.
- A Google Gemini API key from <https://aistudio.google.com/> (create a **new** one; never reuse a key that was shared anywhere).

## Setup (PowerShell)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env        # then edit .env: set GEMINI_API_KEY and SECRET_KEY, keep DEBUG=True locally
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

Open <http://127.0.0.1:8000/>. Edit `.env` in an editor; do not print or share it. `DEBUG` defaults to **False**, and `SECRET_KEY` is required when it is, so a local `.env` with `DEBUG=True` is needed for development.

## Verify Gemini (real network calls)

```powershell
.\.venv\Scripts\python.exe manage.py verify_gemini
```

Lists the models your key can use, confirms the configured embedding/generation models support `embedContent`/`generateContent`, then makes one real embedding and one real generation call. The key is never printed. Without a key it reports `BLOCKED` and performs nothing.

`text-embedding-004` has been retired by Google, so the default is `gemini-embedding-001`; the generation default is `gemini-2.5-flash`. Model availability changes — if `verify_gemini` reports a model missing, set `GEMINI_EMBEDDING_MODEL` / `GEMINI_GENERATION_MODEL` in `.env` to one it lists.

**Changing the embedding model or dimension:** old vectors are incompatible. The app detects this (questions return a clear error instead of mixing vectors). Rebuild with:

```powershell
.\.venv\Scripts\python.exe manage.py reembed
```

```powershell
$env:RUN_LIVE_TESTS = "1"
.\.venv\Scripts\python.exe manage.py test documents.tests.test_live_e2e -v 2
```

## Behaviour and limits

- **File types:** `.pdf` and `.txt`; max size `MAX_UPLOAD_SIZE_MB` (default 10).
- **Scanned / image-only PDFs are not supported.** There is no OCR; such files are marked *Failed* with an explanation.
- Encrypted PDFs (non-empty password) are rejected.
- Processing is synchronous: a large document makes the upload request wait while embeddings are created (batched, 50 per call). Free-tier quotas may cause a "quota or rate limit" failure; retry later.
- Page numbers refer to PDF page order (not printed page labels). TXT files have no page numbers.
- Answers can still be imperfect; always check the cited excerpts.
- No user accounts: anyone who can reach the site can upload, query, and delete. Put it behind authentication/network controls before exposing it publicly.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| "GEMINI_API_KEY is not configured" | Set it in `.env`, restart the server. |
| "rejected the configured API key" | Key is invalid/revoked; create a new one. |
| "model is unavailable" | Run `verify_gemini`; change model env vars. |
| "different embedding model or dimension" | Run `manage.py reembed`. |
| Upload shows *Failed* | Read the message on the dashboard (scanned PDF, quota, corrupt file…). |
| `ImproperlyConfigured: SECRET_KEY` | `DEBUG` is False but no `SECRET_KEY`; set one (or `DEBUG=True` locally). |

## Deployment

Production needs these environment variables: `SECRET_KEY`, `DEBUG=False`, `ALLOWED_HOSTS`, `CSRF_TRUSTED_ORIGINS`, `GEMINI_API_KEY` (set in the host's secret manager, never committed), and the model variables if you override defaults.

```bash
pip install -r requirements.txt
python manage.py migrate
python manage.py collectstatic --noinput
gunicorn intellidocs.wsgi --timeout 180      # Linux hosts; long timeout because ingestion is synchronous
```

With `DEBUG=False` the app enables HTTPS redirect, secure cookies, HSTS (1 h by default), and serves static files via WhiteNoise.
`manage.py check --deploy` reports only the optional HSTS-subdomain/preload advisories.

**Persistence warning:** SQLite (`db.sqlite3`) and uploaded files (`media/`) live on local disk. On ephemeral hosts (many PaaS free tiers) they are lost on restart/redeploy. Use a host with a persistent disk/volume for both, or move to a managed database (e.g. PostgreSQL via `DATABASES`) — not configured here. Uploaded files are only needed during ingestion; extracted text and vectors are stored in the database.

**Status:** prepared for deployment; **not deployed**, and no hosting target has been selected or verified.
